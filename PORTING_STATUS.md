# Current implementation status

> Despite this file's legacy name, this is a **current-code capability map**, not a migration history or roadmap. Source at HEAD remains authoritative. Start with [AGENTS.md](AGENTS.md) and the dated [DEVELOPMENT_HANDOFF.md](DEVELOPMENT_HANDOFF.md); use [PORTING_AUDIT.md](PORTING_AUDIT.md) for call flows. Current package baseline: **RobotRun v1.1.10 / versionCode 12** in `app/build.gradle.kts` (recheck source before citing later versions).

## Implemented runtime

- Native Kotlin Android application (`com.example.cookierunbot`) targeting API 36, minimum API 26, with OpenCV 4.13.0.
- User-approved MediaProjection runs in a foreground service. A latest-only ImageReader pipeline accounts for display changes/cutouts, crops the 16:9 game viewport, and publishes normalized 1280×720 OpenCV frames.
- Process-owned `BotRuntime` keeps the controller independent of `MainActivity` recreation. Capture-service shutdown stops automation.
- OpenCV grayscale `TM_CCOEFF_NORMED` stage detection uses fixed logical ROIs/templates and threshold 0.8. Legacy evaluates seven scales for `GAME_START`/`GAME_RELAY`; the opt-in experimental Redfinger profile checks their native `1.0` templates only and omits handled `GAME_START` in the remainder of the round.
- Accessibility gestures use shared content geometry, serialized dispatch, callback completion/timeout handling, run-generation invalidation, and post-gesture fresh-frame synchronization.
- Current PRE_GAME, IN_GAME, and POST_GAME workflows cover menu/start/purchase, random boost, Fast Start, Cookie Relay, jumping, game completion, result capture/OCR, Mystery Boxes, reward/daily/league/relic/party/settings popups, anti-bot, Login, Connection Lost, and Inactive handling. Login is primary in PRE_GAME/POST_GAME but background/recovery-only in IN_GAME (and skipped during the Fast Start priority window), at scale 1.0 inside ROI `(390,570)-(890,700)`; the first action uses the detected template center rather than a fixed Login coordinate, waits 5 seconds, then taps the Google logo at logical `(657,294)` with zero jitter. The handler then searches `LOGIN_ACCOUNT_PICKER_1.png` in ROI `(270,75)-(1010,285)` for up to 60 seconds; a match taps the profile circle at logical `(323,299)` with zero jitter, while timeout ends the Login flow without another tap. PRE_GAME resumes in both cases. Anti-bot Test 1→2→3 follow-up compares all six card slots as well as the whole layout; same-artwork shuffles advance only when moved slots match other baseline artwork as a real permutation cycle and remain stable for two fresh frames, without loosening the stage template/ROI/threshold. If follow-up remains continuously visible with no tap/layout progress for 60 seconds, a three-fresh-frame emergency verification can bypass only the layout guard and reuse the existing odd-card tap path; Test 3 awaiting-exit is excluded and failed attempts wait another 60 seconds. An active follow-up remains one statistics challenge even past the legacy two-minute gap.
- Scheduled/manual Friend Life and per-round Quick Receive/Send Lives are independent, bounded workflows with interrupt scans and fresh-frame checks. Friend Life additionally uses naturalized swipes and visual scroll verification. Its successful Confirm gestures re-arm the 60-second high-confidence stuck-Confirm timer so popup instances cannot inherit elapsed time. In normal PRE_GAME/POST_GAME detection, a tracked high-confidence Confirm also gates any newly matched state behind a strictly newer full-frame recheck: persistent Confirm is handled first; disappearance discards the stale state result and returns to redetection.
- The League-ended restart notice is a dedicated PRE_GAME/POST_GAME reward popup (`LEAGUE_ENDED_RESTART`) using the supplied text template, normalized ROI `(330,160)-(934,412)`, scale 1.0, and Confirm `(640,458)`; it is intentionally absent from IN_GAME and full-recovery stage order.
- A 15-minute progress watchdog can launch gated confirm/close recovery and send one successful Telegram warning per overdue episode. It resets only for bot start, detected game completion, or successful Friend Life Send-button gesture.
- Telegram configuration, encrypted token storage, asynchronous notifications, authorization to the configured Chat ID/token identity, retry policy, and a persistent one-tap reply keyboard are present. Read-only commands: `/help`, `/status`, `/stats`, `/last`, `/boxes`, `/all`, `/friend`, `/health`, `/screen`, `/watchdog`, `/rounds`, `/errors`, `/update`, `/logs`, `/dashboard` (`/start`/`/menu` aliases). `/all` and `/screen` export the fresh 1280×720 frame as an original PNG `sendDocument` file. The Telegram-only encoder converts the snapshot clone from RGBA to BGRA before OpenCV encodes it; this does not touch capture/detection/gameplay or the existing automatic diagnostic `sendPhoto` path. `/all` then sends one `/stats` → `/status` → `/last` text even if the document fails; their on-demand image path shares a 15-second cooldown. The **📦 Update App** button maps to `/update`, which checks the in-app HTTPS feed and, on a newer release, verifies its APK checksum/package/version/installed signer, then streams it to the configured Telegram chat (49,000,000-byte cap). A dedicated worker handles it independently of the watchdog notification queue; no remote installation or gameplay stop.
- Session statistics maintain bounded recent history plus cumulative totals with replacement/delta semantics. Session Runtime uses one shared day-aware formatter in Telegram stats, Statistics, and the overlay: 24h becomes `1 day`, with later days/hours/minutes shown without resetting the session clock. Result/no-match images and in-app/persistent logs are implemented.
- Bubble UI persists bot options, including opt-in Experimental Redfinger Performance Profile. Active gameplay options are a start-time snapshot; the two image-save preferences are intentionally queried live.
- Main-screen **Update App** works without Telegram. An owner-configured anonymous HTTPS feed supports manual check/download with bounded size, SHA-256, package/version and installed-signing-certificate verification; an offline document-picker APK path enforces newer version/package/certificate. Both stage a verified APK in app-private cache and launch Android's consent-driven installer only after the operator manually stops Bot and capture.

## Deliberate boundaries and current limitations

- MediaProjection, overlay, Accessibility, notification, and battery settings still require user action; automation cannot silently grant them.
- Overnight Diagnostics mirrors RobotRun-owned Logcat/DebugLogStore/PersistentTrace messages into a rolling 10h archive (200 MiB cap), separate from the 500-line RAM Debug Log. Each real overdue or accepted manual Watchdog Recovery freezes 30m of text, Bot/Capture status and normalized 1280×720 PNG, then records ordered action timeline/outcome; Incidents retain up to 72h/200 MiB separately. The legacy-named `IncidentVideoRecorder` now runs an **optional JPEG screenshot sequence** only after an Incident trigger: dormant during gameplay, no pre-roll, 480×270 q35 once per 2s (0.5 FPS), max 90 images / 20 MiB, Recovery finish+10s or trigger+3min (earlier), plus capture/resource early stops. Capture FPS must be known and >=2; repeated/stale frames, app-process CPU pressure >1 core-equivalent in 2s, or an expensive sample (>250ms wall / >80ms thread CPU) yield; the expensive sample backs off one tick, while ten consecutive degraded ticks terminate. No MP4 encoder for new Incidents; completed JPEGs and timing/status remain, legacy MP4 evidence can still be exported. This is not a measurement of entire Redfinger VM CPU. Essential screenshot/archive precedes optional work; no new MediaProjection or gameplay wait. Manual `/logs` and 📥 Download Logs export ZIP with up to five recent Incidents, and Save 10h ZIP is local fallback. Redfinger sampling performance must be validated on-device. See [docs/OVERNIGHT_DIAGNOSTICS.md](docs/OVERNIGHT_DIAGNOSTICS.md).
- The still-frame Coordinate Calibration tool has a screen-orientation-aware overlay: fixed, always-visible ✕ Close header above the scroll area; display-specific metrics and configuration/display resize callbacks; usable bounds exclude system bars/cutouts. Rotation retains the captured 1280×720 frame and its original transform without performing any gameplay action. Explicit recapture is needed for current physical X/Y. See [CALIBRATION.md](CALIBRATION.md).
- Detection is calibrated for normalized 1280×720 content and current assets/ROIs. Device/cutout behavior and gesture calibration require real-phone validation. The Redfinger performance profile is opt-in (not selected by resolution) and makes narrowly scoped capture, NO_MATCH scoring, matching-scale and calibrated-post-relay changes; see [REDFINGER_PERFORMANCE_PROFILE.md](REDFINGER_PERFORMANCE_PROFILE.md).
- Fixed-device gesture exceptions are the isolated absolute 2400×1080 `POST_RELAY_*_PHYSICAL` points, TIME_DEAL at physical `(2000,70)`, and PARTY_RUN_SEASON_REWARDS at physical `(1260,980)`; they bypass normalized mapping and are not general coordinate policy.
- The current watchdog CLOSE_BUTTON fallback uses grayscale `detectTemplate()` / `TM_CCOEFF_NORMED` with threshold 0.8 in the top-right quarter, not the alpha-mask SQDIFF helper. It stops on no-match or after three matched taps; a successful callback is followed by the 2-second retry delay when another attempt remains, then a post-delay generation baseline and a strictly newer frame (the final tap has no retry delay but still gets a fresh frame). MAINMENU detection then examines that frame and subsequent fresh frames for up to 120 seconds and routes a match to PRE_GAME.
- Connection Lost/Inactive use Reload taps only. The app does not force-stop or restart Cookie Run or RobotRun.
- No-match and detector-stall signals save/log local diagnostics and do not create a second Telegram alert path.
- Telegram commands are read-only and restricted to the configured Chat ID; there is no remote Start/Stop/gameplay control or remote APK installation. Users must install an APK containing new Kotlin Telegram keyboard/command code, then use `/dashboard` to refresh its persistent keys. The BotFather slash-command menu is separate.
- The GitHub Actions workflow is manual (`workflow_dispatch`) and builds a signed debug APK only when required repository secrets exist; artifacts expire after 14 days. Once signature verification passes, it copies the APK with version/versionCode/commit/run/attempt in its filename and gives the downloadable ZIP the same stem, avoiding repeated `app-debug.apk` filenames after extraction. The standard Gradle output remains unchanged. It does not publish a release build, hosted HTTPS feed or installable OTA release. The private source repo must not be exposed or shipped with an embedded access token. A future in-place update must use the same signing certificate as the installed APK; different Android Studio and CI debug signing keys cannot overwrite each other while keeping user data.
