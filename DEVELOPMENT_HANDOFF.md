## Project identity and current release baseline

- Repository: `thanawatch/BotAndroid`, branch `master`; native Android Kotlin app **RobotRun** for Cookie Run Classic. No Python-runtime dependency in the Android app.
- Package/application ID: `com.example.cookierunbot`. Version baseline in `app/build.gradle.kts`: **v1.1.8 / versionCode 10** as of this handoff. Increment the integer version code on every subsequent installable release; the human-readable name can follow `major.minor.patch`. Verify values in source before claiming them.
- Target: actual Android devices and Redfinger; capture via MediaProjection, OpenCV matching, gestures via AccessibilityService. Runtime controller is process-owned, not Activity-owned.
- Standard frame/action system: cutout-safe dynamic `contentRect`, normalized **1280×720** `Mat` and matching logical coordinates. Never hard-code an inferred physical offset or bypass `CoordinateMapper` except for the explicitly documented legacy fixed-device exceptions. The Redfinger profile has separately calibrated logical post-relay targets.
- [PORTING_STATUS.md](PORTING_STATUS.md) is the concise capability inventory; [PORTING_AUDIT.md](PORTING_AUDIT.md) explains current call paths; [REDFINGER_PERFORMANCE_PROFILE.md](REDFINGER_PERFORMANCE_PROFILE.md) defines the experimental opt-in profile; [ANDROID_TEST_CHECKLIST.md](ANDROID_TEST_CHECKLIST.md) is the unverified device checklist.

## Changes must stay narrow

1. Inspect `git status`, target call sites, tests and the current options before editing. Preserve unrelated edits. Do not casually change known-good templates, ROIs, thresholds, stage order, Friend Life swipe/calibration/scroll verification, or state transitions.
2. Keep screenshot capture and gesture mapping on the same immutable transform. `LatestFrameProvider` is latest-only; clients own snapshot clones and must release them. Do not treat frame captured during a gesture as post-gesture evidence.
3. `CONNECTION_LOST` and `INACTIVE` are **Reload-only**. Do not introduce force-stop/process kill/restart, random taps, old announcement-closure tap loops, or broad speculative recovery.
4. Friend Life is separate from Quick Lives. Preserve scheduler interval and queued/manual semantics, send flow `SEND_BUTTON -> CONFIRM_1 -> CONFIRM_2`, existing swipe coordinates/visual scroll verification, and bounded timeouts. Do **not** add button-disappearance/post-send verification or unrequested extra frame scans. Only a **successful Send-button gesture callback** resets watchdog progress, not matching the template or completing later confirmations.
5. The 15-minute watchdog starts at BOT_START and resets for confirmed `GAME_COMPLETE` (immediately, before result handling) and successful Friend Life Send-button gesture only. Prevent stale-frame duplicate resets and callback crossing run/episode boundaries. Overdue Telegram warning is at most one successfully delivered warning per progress episode; failed delivery retry waits at least five minutes and honors server `retry_after`. No automatic NO_MATCH/DETECT_STALL Telegram messages.
6. Telegram is **read-only**, authorized to the configured Chat ID and token identity. No remote Start/Stop/tap/reload/install commands. Async network/image work must not stall capture, detection or main UI.
7. Any new updater must require explicit Android/user installation confirmation, never stop the bot or Screen Capture automatically, never silently install/restart the game, and never embed a private GitHub token, Chat ID, signing key or URL containing credentials.

## Existing performance profile: do not flatten it into Legacy

- **Legacy** is default; **Experimental Redfinger Performance Profile** is opt-in from the overlay and snapshotted at Start Bot. Resolution alone does not select it.
- In Redfinger, GAME_START and GAME_RELAY match only scale 1.0; handled GAME_START is omitted for the rest of that round. Legacy retains its seven scales for both. Redfinger skips expensive IN_GAME detailed NO_MATCH rescoring, retaining light diagnostics and normal detection. Exact uncut 1280×720 capture uses a copy rather than unnecessary resize.
- Redfinger post-relay logical points are `(1198,35)`, `(647,425)`, `(637,389)`, mapped through the current `contentRect`. Legacy's fixed 2400×1080 physical paths remain isolated.
- Uncalibrated Redfinger TIME_DEAL and PARTY_RUN_SEASON_REWARDS must block and wait for manual popup clearance; never guess coordinates. See the profile document for benchmarking, limits, and tests.

## Telegram: current product surface

- Available commands: `/help`, `/status`, `/stats`, `/last`, `/boxes`, `/all`, `/friend`, `/health`, `/screen`, `/watchdog`, `/rounds`, `/errors`, `/update`, `/logs`, `/dashboard`. `/start` and `/menu` are dashboard aliases; supported slash commands accept the existing `@BotUsername` parser form.
- A **persistent reply keyboard** accompanies command replies; `📊 All` and `🔄 Refresh` both trigger `/all`, and `📦 Update App` triggers `/update`; `📥 Download Logs` triggers `/logs`. Changing Kotlin keyboard definitions requires a newly installed APK; send `/dashboard` after updating to refresh Telegram's displayed keyboard. BotFather slash-command menu is a separate Telegram setting, not automatically changed by the APK.
- `/all`: attempt a fresh **1280×720 original-quality PNG document first** (Telegram `sendDocument`), then send the single unchanged `/stats -> /status -> /last` text snapshot. `/screen` uses the same document upload. The Telegram-only PNG encoder converts a cloned RGBA Mat to separate BGRA before OpenCV `imencode`, without changing detection frames or the existing automatic `sendPhoto` diagnostic path. If photo/capture is unavailable, stale, upload fails or the shared 15-second `/screen`/`/all` cooldown applies, the entire text still arrives with a short Screen note.
- `/friend`, `/health`, `/watchdog`, `/rounds` (up to five recent), `/errors` (requested, allowlisted recent lines) are diagnostic-only; do not add remote gameplay controls. Manual command replies can work when automatic text notifications are disabled.
- `/update` checks the feed configured in the Android Update App screen. When it advertises a newer release, a separate `telegram-apk-delivery` worker downloads into its own cache, verifies SHA-256 plus package/version and the installed signing certificate, and streams an APK document to the authorized chat (max 49,000,000 bytes). One request at a time; the same successfully sent checksum is held back for five minutes. Too-large/invalid/unavailable APKs return an in-app updater fallback. Telegram NEVER installs the app, stops the bot or touches the game's workflow. The user downloads the received file on Android/Redfinger and confirms the system installer. Requires an already-installed APK with this feature, plus a genuine accessible HTTPS feed.
- Owners: `notifications/TelegramCommandReceiver.kt`, `TelegramNotifier.kt`, `TelegramDashboardPolicy.kt`, `TelegramDashboardReplies.kt`, `TelegramUpdateReply.kt`, `TelegramScreenshotEncoder.kt`, `TelegramScreenshotMultipart.kt`, `TelegramApkDelivery.kt`; tests live in matching `app/src/test/` package.

## Updating the APK without Telegram

- `MainActivity` opens `UpdateActivity` via **Update App (no Telegram required)**.
- Online: user configures an anonymous trusted HTTPS `update.json` URL, taps Check, then Download. Feed fields: `packageName`, `versionCode`, `versionName`, `apkUrl`, `sha256` (64 hex), optional `notes`. The online download checks SHA-256, size, matching package/version and the installed app's signing certificate; redirects stay HTTPS.
- Offline: **Choose downloaded APK (offline)** uses Android's document picker. A selected local APK still must be newer, have the same package and certificate, and meet the size limit. This route does not use a published feed or claimed online checksum.
- Cache: app-private `cache/updates/`, shared read-only with the Android installer via a restricted non-exported FileProvider. Installer source permission and the Android install dialog are user-controlled; block installer launch while Bot or Screen Capture runs.
- **Publication remains a separate operator task, not an implemented automatic release channel.** The private GitHub repo has a manually dispatched signed-debug-APK workflow with 14-day Actions artifact retention. After verifying the original `app-debug.apk`, the workflow reads version metadata and creates a uniquely named downloadable copy plus matching Artifact ZIP: `RobotRun-v<versionName>-vc<versionCode>-g<shortSHA>-run<runNumber>-a<runAttempt>-signed-debug.apk`. Do not change versionCode merely to distinguish repeated Builds; the file label identifies the exact build. That artifact is not an anonymous permanent feed/download. No public feed, release URL, published APK, completed device installation or unattended OTA success should be claimed without actual evidence. The owner must host a signed APK plus feed on trusted HTTPS, using the **same signing certificate as the installed app**. A different local Android Studio debug key and CI key cannot update in place while preserving data.

## Overnight Diagnostics and Incident Video

- A separate `RobotLog` facade mirrors RobotRun-owned Android Logcat events, while `DebugLogStore` and `PersistentTrace` also feed a private rolling UTC-hour text archive. Archive export is last 10h by event timestamp, with 200 MiB size cap and loss markers. The in-app Debug Log remains 500 RAM preview lines; **Save 10h ZIP** is a separate export. Never imply a full day's data if the bounded queue or cap pruned events.
- Every real watchdog overdue or explicit manual-test Recovery reservation freezes 30 minutes of archived logs, current status and screenshot into a 72h-retained Incident (separate 200 MiB cap). Its action timeline observes `[GAME_PROGRESS_*]` including physical/logical target, accepted gesture, completed callback and post-action frame; final recovery result is recorded. Does not change 15m watchdog, progress-reset rules, detector, template, ROI, Recovery attempt limits or gameplay.
- `IncidentVideoRecorder` is ARMED but does no recurring frame work before Incident. A real/manual Watchdog Incident triggers optional 2 FPS / 640×360 JPEG40 capture (no pre-roll), ending at **Recovery finish +10s** or **3min after trigger**, whichever earlier, or sooner under stale/slow capture/size pressure. Separate lowest-priority MP4 H.264 250kbps encode yields between frames and may be skipped/aborted on capture/session/app CPU pressure; keep JPEG/status fallback. The sampler checks thread CPU >80ms, wall >250ms and sustained process load >1.5 single-core equivalents in 2s. Session fencing protects a quick stop/restart; do not claim this measures the entire Redfinger VM CPU. The explicit manual test creates a labeled MANUAL_TEST Incident without resetting true watchdog timer. Toggle is in Debug Log; no second MediaProjection. Never block gameplay for video.
- Manual authorized `/logs` and **📥 Download Logs** deliver an original ZIP through a distinct `telegram-log-delivery` executor, 49,000,000-byte limit; includes 10h text and at most five newest Incidents, videos subject to a 35 MiB raw budget. Auth is rechecked while streaming, and no automatic log upload occurs. An oversized file can be exported locally via **Save 10h ZIP**. The Telegram receiver cannot answer while the entire app process is killed; saved private files remain available after restarting the app. Consult [docs/OVERNIGHT_DIAGNOSTICS.md](docs/OVERNIGHT_DIAGNOSTICS.md).
- This version introduces new MediaCodec/MediaMuxer behavior that has **not** been proven on Redfinger until Gradle, device record/playback and background-lifetime tests actually pass.

## Orientation-safe calibration panel

- `CoordinateCalibrationOverlay` displays a captured, immutable 1280×720 frame. The overlay is a separate WindowManager window, not an Activity; when leaving the landscape game, Android can switch the display to portrait while the window remains open. The old fixed 620dp layout left its close button off-screen.
- It now uses a display/window Context where supported, listens for configuration/display changes, and resizes within the current inset-adjusted viewport. A **persistent ✕ Close header is outside the scrolling controls**. Rotation changes only the overlay layout, never sends an Accessibility gesture, changes game handlers or silently recaptures.
- The original still's `ContentTransform` remains attached to that capture. After rotation, use **Capture new clean frame** for current physical X/Y. Display/config callbacks are unregistered when the panel closes; errors restoring layout close it and restore the parent bubble.
- For an old installed build stuck with an invisible Close button, rotate back to landscape or temporarily disable RobotRun's Android **Display over other apps** permission. See [CALIBRATION.md](CALIBRATION.md) and [ANDROID_TEST_CHECKLIST.md](ANDROID_TEST_CHECKLIST.md).
